# Safe admission-wait expiry and explicit continuation: source history

This directory preserves the exact predecessor sources for the admission-wait expiry and explicit continuation implementation. Its manifest distinguishes the current 60-module runtime from earlier reviewed sources. It does not turn earlier installed runs into validation of the new code.

The implementation reuses the existing TaskStore owner claims and SQLite transaction, mailbox request/acknowledgement prefixes, resource cleanup and selected-execution lifetime. A safe expired wait retains its pending provider request and saved conversation. A new explicit Continue grant records a typed, digest-bound supersession of that request; only the successor rebuilds the next SDK turn. The original request, prompt, history, effects and cumulative request accounting remain preserved.

The SDK behavior is derived from the pinned Hermes public [turn facade](https://github.com/NousResearch/hermes-agent/blob/14e1e43a23761b369641208e204365cd6cb9399d/agent/turn_facade.py) and [turn context builder](https://github.com/NousResearch/hermes-agent/blob/14e1e43a23761b369641208e204365cd6cb9399d/agent/turn_context.py). It rebuilds a turn from saved conversation and a new Continue message; this is not a claim that an old provider request is replayed byte for byte. Atomic selection uses the repository's existing [SQLite transaction](https://www.sqlite.org/lang_transaction.html) mechanism. No alternate provider executor or automatic budget renewal is introduced.

The existing source-preservation helper validates complete current bytes and the cross-version AST fingerprint before exposing exact retained predecessor bytes. The old alias, pause-observation, diagnostic and installed-evidence manifests stay unchanged. The pause-observation test reads an explicitly reconstructed source view before its original assertions; a new regression verifies that its preserved source restores byte for byte. Retained runtime sources are parsed for comparison, never loaded as an alternative implementation.

The new checks cover successor and predecessor mutation refusal, complete runtime identity, unchanged historical manifest identities and exact restoration of the older helper/test assertions. Existing source-history tests continue through the same helper. Run the ordinary repository test suite to exercise current behavior separately. Component tests, SDK tests without a model, installed validation and actual model workload acceptance are distinct evidence boundaries.
